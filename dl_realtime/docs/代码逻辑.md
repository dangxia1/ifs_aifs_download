# dl_realtime 代码逻辑

> 3161 实时预报下载管线：下载 → 缓存 → IVT → AR → 可视化

## 总览

```
每小时 cron 触发 → dl_realtime.py
  │
  ├─ 1. 读取缓存 (.last_run)
  ├─ 2. 逐模型检查时次是否更新（ifs / aifs-single）
  │     ├─ 未更新 → skip
  │     └─ 更新 → 下载 grib2
  ├─ 3. 写入缓存
  ├─ 4. 清空旧 ivt/ ar/ 目录
  ├─ 5. 计算 IVT (9 个 _ivt.nc)
  ├─ 6. AR 检测 (9 个 _ar.nc)
  └─ 7. 可视化 (27 张 PDF)
```

## 模块结构

| 模块 | 作用 |
|------|------|
| `dl_realtime.py` | 主流程（下载/调度/串联） |
| `utils.py` | 配置加载、日志、时次获取、下载重试、路径 |
| `compute_ivt.py` | IVT 计算（1000-300 hPa 垂直积分） |
| `detect_ar.py` | 大气河识别（来自 dl_lastmonth_cal_ivt，复用） |
| `visualize_ivt.py` | 3 区域可视化（全球/东亚/华北） |
| `config_realtime.yaml` | 配置 |

## 各阶段详情

### 1. 读取缓存（对齐时次）

- 文件：`{save_dir}/.last_run`
- 格式：单行 `YYYY-MM-DD THHz`，如 `2026-08-02 06z`
- 含义：上一次成功下载的**对齐时次**（IFS 和 AIFS 取较旧者，保证对比图同一起报）

### 2. 时次检查（双模型对齐）

1. `Client.latest()` 分别获取 IFS / AIFS 最新时次
2. `aligned = min(ifs_latest, aifs_latest)` — 取两者都有的最新时次
3. 与缓存比对：
   - **相同** → 检查 figures 完整性：
     - 完整（≥75 PNG）→ 直接退出（下载/IVT/AR/可视化全跳过）
     - 不完整 → **只重画图**（数据不变，跳过下载/IVT/AR，仅可视化+时序图）
   - **不同** → 全流程：下载 → IVT → AR → 可视化

为什么取 min？IFS 和 AIFS 发布时间不同步（IFS 先完成，AIFS 晚几十分钟），对比图必须同一起报时次，慢的那个决定节奏。

### 3. 下载 grib2

对每个模型 × 每个 step（0-144h 步长 6h，25 个时次）：

1. `clear_model_dir()` 清空该模型 grib2 目录（只保留最新）
2. 对每个 step：
   - 分两次请求下载：地面场（`tp`）+ 气压层场（q/u/v/t/gh × 9 层）
   - 二进制拼接合并为单个 grib2
   - `eccodes` 校验要素齐全
   - 校验失败重试（最多 3 次）
3. 任一 step 失败 → `return 1` 退出，缓存不写

下载完成后**立即写缓存**——即使后续 IVT/AR/可视化失败，下次运行也不会重复下载。

### 手动操作对照

| 操作 | 效果 |
|------|------|
| `rm .last_run` | 全流程重跑（重新下载 ~1.3GB + IVT + AR + 图，约 1.5h） |
| `rm -rf figures/` | 只重画图（缓存命中 + figures 不完整 → 快速重新出图，几分钟） |

### 4. 清空旧 IVT/AR

删除 `ivt/{ifs,aifs}` 和 `ar/{ifs,aifs}` 全部旧文件，只保留本次结果。

### 5. IVT 计算

对 9 个 grib2 逐个：

$$IVT = \frac{1}{g} \int_{300}^{1000} q \cdot \mathbf{V} \, dp$$

- 梯形法则，6 层（1000/925/850/700/500/300 hPa）
- 输出 `_ivt.nc`：`IVT`、`IVT_u`、`IVT_v`，单位 kg·m⁻¹·s⁻¹

### 6. AR 检测

对 9 个 `_ivt.nc` 检测，**跳过已存在的 `_ar.nc`**（断点续传），**多进程并行**：

1. 加载阈值：老师的 ERA5 1981-2023 逐月 85% 分位 pckl
2. 按当前月份取 5 个月滑动平均（前后各 2 个月）
3. 阈值扩展 3 倍匹配经度循环
4. 检测流程：阈值二值化 → 形态学填充 → 骨架化 → FilFinder2D 精炼 → 几何过滤（长度/面积轴比/热带占比/风向一致性）
5. 输出 `_ar.nc`：`AR_plume`、`AR_axis`、`AR_center`、`AR_IVT`

**并行策略**：用 `mp.Process`（非 daemon）分批，每批 4 个进程，join 后再下一批。

> ⚠️ 不能用 `mp.Pool`——其 worker 是 daemon 进程，而 FilFinder2D 内部会再开子进程，触发 `daemonic processes are not allowed to have children` 错误。

子进程结果通过 `print` 输出到终端（`flush=True`），不写主日志文件。单个文件失败不影响其他。

### 6.5 AR 时间连续性平滑（方案 B）

单时次独立检测的 AR 会在相邻时次（6h）间"时断时续"跳变，物理上不合理、展示上影响可读性。平滑以时间连续性为约束，**只补不删**：

- **滑动窗口加权投票**：每格点 score(t) = Σ w_k · AR(t+k) / Σ w_k，窗口 5 帧（t-2..t+2），高斯型权重 [0.15, 0.25, 0.30, 0.20, 0.10]（中心帧最大，越远贡献越小）；边界帧分母按实际存在帧归一化
- **补 AR 条件**：score ≥ 0.25 **且** IVT ≥ 250 kg·m⁻¹·s⁻¹（与 5 级色标下限一致，防止把弱水汽噪声补成 AR）
- **只补不删**：原始检测到的 AR 恒保留，平滑仅补全缺失帧，避免修正过度删掉真实 AR
- 实现：`visualize_ivt._smooth_ar_temporal`，画图前预读全时次 plume+IVT 一次性平滑；平滑后的 plume 用 `_compute_axis_center` 重算河轴/质心（保证轴/心与最终 plume 一致）

**双向恢复（消亡 + 生成，老师方案 2026-08-06 及补充）**：

投票补全只对"逐格点小缺失"有效；整条河消失时相邻帧无 AR，score≈0 补不出来，表现为"48h 后信号突然中断"。新增双向恢复机制（老师要求：生成机制 = 消亡机制逆向）：

- **双向扫描**：沿时间序检查每个"当前无 AR"的时次——
  - **消亡恢复**：前一时次有 AR → 用前 mask 作先验恢复当前（大 AR 不该瞬断）
  - **生成恢复**（逆向）：后一时次有 AR → 用后 mask 作先验恢复当前（AR 生成过渡帧补全）
- **触发（三个条件同时满足，先验时次 = 前/后一时次）**：
  1. 当前时次无 AR、先验时次有 AR（突然消失/出现）
  2. 先验时次河轴长度 > 2500 km（轴长 = `_compute_axis_center` 在平滑后 mask 上现算的主轴长度 × 纬向格距；不依赖原始轴——原始轴被 FilFinder 修剪后可能为空导致误判不触发）
  3. 先验 mask 范围内，当前时次 IVT 最大值 > 500 kg·m⁻¹·s⁻¹（水汽仍在 → 漏检而非消亡/生成）
- **恢复动作**：在先验 mask 膨胀邻域（10 格）内，用**熵权法**融合两个指标重新识别 mask：
  - 指标 1：本时次 IVT 强度（区域内 min-max 归一化）
  - 指标 2：与先验 mask 的空间邻近度（距离先验，mask 内=1、向外衰减）
  - 熵权法按信息熵客观赋权（信息熵越小 → 权重越大：先验越确定先验主导，反之 IVT 主导），综合得分 ≥ 0.5 且 IVT ≥ 500 → 恢复为 AR；恢复 mask 做闭运算连片（避免破碎 → 质心杂乱）
- 河轴由调用处 `_compute_axis_center` 在恢复 mask 上重算；恢复出的 mask 供下一时次继续判定
- 常量：`AXIS_LEN_REVIVE_KM / IVT_REVIVE_MAX / REVIVE_DILATE / REVIVE_SCORE_TH / REVIVE_IVT_MIN`（visualize_ivt.py 顶部，可调）
- 触发时终端打印 `AR 消亡恢复/生成恢复: 时次t ...`，便于核对哪些时次被恢复

### 7. 可视化（预报图）

对 25 个 step × 3 区域 = **75 张 PNG**，每次运行先清空旧图。

**双面板布局**：

| 区域 | 布局 | 范围 |
|------|------|------|
| global | **上下**（IFS 上 / AIFS 下） | -179~180°E, -88~88°N |
| east_asia | 上下 | 73-160°E, 10-55°N |
| north_china | 左右 | 105-125°E, 30-50°N |

**画法**（导师 Basemap 风格）：

- 暗色背景 + `bluemarble` 卫星底图
- 灰色海岸线、白色经纬网标签
- `contourf` 双层 + `contour` 薄黑线：
  - 全 IVT 场 alpha=0.2（非 AR 区淡）
  - AR plume 内 alpha=1（AR 区浓）
- **cmap：AR 强度 5 级**（导师要求）：蓝/黄/橙/橙红/红，IVT 250-500 / 500-750 / 750-1000 / 1000-1250 / 1250+
- AR 河轴：紫色散点（华北放大 + 白描边，亮底图可见）
- AR 质心：白心黑边十字（先大黑十字打底再白十字覆盖，亮暗背景均可见）
- 河轴短段过滤阈值：全球/东亚 20 像素，华北 5 像素（窗口仅 80×80 格，主链被窗口截短，20 像素会把轴整段误删）
- 华北区域：北京红星标注
- **标题**：`IFS 2026/08/04 20:00`（起报北京时间 + step = 预报时间）
- 色标：底部水平，附中文等级说明

**中文字体**：项目 `fonts/` 内置 Noto CJK（OFL 可分发），代码优先从项目内加载，服务器/绿色包/本地一致。

### 8. 华北 AR 强度时间序列（时序图）

`north_china_timeseries.py`，输出 `figures/north_china_timeseries.png`：

## 关键设计决策

| 决策 | 原因 |
|------|------|
| 逐模型独立时次 | IFS/AIFS 上线不同步 |
| 缓存下载完即写 | 避免后续阶段失败导致重复下载 |
| 每小时跑但只下载 4 次/天 | ECMWF 约 6h 更新一波，缓存过滤无效运行 |
| AR 跳过已存在文件 | 中断后重跑只补缺失，不重复检测 |
| AR 用 mp.Process 分批并行 | Pool 的 daemon 进程无法再开子进程（FilFinder2D 内部需要） |
| IVT/AR 单文件容错 | 一个文件失败不中断整条管线 |
| 下载失败即退出 | grib2 不完整会导致后续全部失败 |
