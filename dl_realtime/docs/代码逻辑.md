# dl_realtime 代码逻辑

> 3161 实时预报下载管线：下载 → 缓存 → IVT → AR → 可视化

## 总览

```
每小时 cron 触发 → dl_realtime.py
  │
  ├─ 1. 读取缓存 (.last_run)
  ├─ 2. 逐模型检查时次是否更新（ifs / aifs-single）
  │     ├─ 未更新 → skip
  │     └─ 更新 → 下载 grib2
  ├─ 3. 写入缓存
  ├─ 4. 清空旧 ivt/ ar/ 目录
  ├─ 5. 计算 IVT (9 个 _ivt.nc)
  ├─ 6. AR 检测 (9 个 _ar.nc)
  └─ 7. 可视化 (27 张 PDF)
```

## 模块结构

| 模块 | 作用 |
|------|------|
| `dl_realtime.py` | 主流程（下载/调度/串联） |
| `utils.py` | 配置加载、日志、时次获取、下载重试、路径 |
| `compute_ivt.py` | IVT 计算（1000-300 hPa 垂直积分） |
| `detect_ar.py` | 大气河识别（来自 dl_lastmonth_cal_ivt，复用） |
| `visualize_ivt.py` | 3 区域可视化（全球/东亚/华北） |
| `config_realtime.yaml` | 配置 |

## 各阶段详情

### 1. 读取缓存

- 文件：`{save_dir}/.last_run`
- 格式：每行 `模型名 日期 时次z`，如 `ifs 2026-07-31 06z`
- 目的：记录每个模型上一次成功下载的起报时次

### 2. 逐模型检查

对 `MODELS`（ifs、aifs-single）逐个：

1. `Client.latest()` 获取 ECMWF 服务端最新可用时次
2. 与缓存比对：
   - **相同** → 日志 `[unchanged, skip]`，跳过该模型
   - **不同** → 下载流程

为什么逐模型？IFS 和 AIFS 发布时间不同步（IFS 先完成，AIFS 晚几十分钟）。

### 3. 下载 grib2

对每个模型 × 每个 step：

1. `clear_model_dir()` 清空该模型 grib2 目录（只保留最新）
2. 对每个 step（IFS: 0/3/6/24/72，AIFS: 0/6/24/72）：
   - 分两次请求下载：地面场（`tp`）+ 气压层场（q/u/v/t/gh × 9 层）
   - 二进制拼接合并为单个 grib2
   - `eccodes` 校验要素齐全
   - 校验失败重试（最多 3 次）
3. 任一 step 失败 → `return 1` 退出，缓存不写

下载完成后**立即写缓存**——即使后续 IVT/AR/可视化失败，下次运行也不会重复下载。

### 4. 清空旧 IVT/AR

删除 `ivt/{ifs,aifs}` 和 `ar/{ifs,aifs}` 全部旧文件，只保留本次结果。

### 5. IVT 计算

对 9 个 grib2 逐个：

$$IVT = \frac{1}{g} \int_{300}^{1000} q \cdot \mathbf{V} \, dp$$

- 梯形法则，6 层（1000/925/850/700/500/300 hPa）
- 输出 `_ivt.nc`：`IVT`、`IVT_u`、`IVT_v`，单位 kg·m⁻¹·s⁻¹

### 6. AR 检测

对 9 个 `_ivt.nc` 检测，**跳过已存在的 `_ar.nc`**（断点续传），**多进程并行**：

1. 加载阈值：老师的 ERA5 1981-2023 逐月 85% 分位 pckl
2. 按当前月份取 5 个月滑动平均（前后各 2 个月）
3. 阈值扩展 3 倍匹配经度循环
4. 检测流程：阈值二值化 → 形态学填充 → 骨架化 → FilFinder2D 精炼 → 几何过滤（长度/面积轴比/热带占比/风向一致性）
5. 输出 `_ar.nc`：`AR_plume`、`AR_axis`、`AR_center`、`AR_IVT`

**并行策略**：用 `mp.Process`（非 daemon）分批，每批 4 个进程，join 后再下一批。

> ⚠️ 不能用 `mp.Pool`——其 worker 是 daemon 进程，而 FilFinder2D 内部会再开子进程，触发 `daemonic processes are not allowed to have children` 错误。

子进程结果通过 `print` 输出到终端（`flush=True`），不写主日志文件。单个文件失败不影响其他。

### 7. 可视化

参照导师 Basemap 暗色风格画法，对 9 个文件 × 3 区域 = **27 张 PDF**：

| 区域 | 投影 | 范围 | 经纬步长 |
|------|------|------|----------|
| global | PlateCarree | -179~180°E, -88~88°N | 30° |
| east_asia | PlateCarree | 105-150°E, 10-50°N | 10° |
| north_china | PlateCarree | 113-120°E, 35-45°N | 2° |

**画法**（模仿导师 Threshold.py 风格）：

- 暗色背景（`facecolor="black"`）
- 灰色海岸线（无国界，政治不正确）
- 灰色虚线经纬网，白色标签
- `contourf` 双层 + `contour` 薄黑线叠加：
  - 第 1 层 contourf：全 IVT 场，`alpha=0.2`（非 AR 区淡）
  - 第 2 层 contourf：AR plume 内 IVT，`alpha=1`（AR 区浓）
  - contour 薄黑线（`linewidths=0.1`）叠加于两层之上，提供结构感
- cmap：`nipy_spectral_r` truncation `0.2-0.9`（去掉两端极端色）
- IVT 层级：50~850 kg·m⁻¹·s⁻¹，步长 50
- AR 河轴：紫色散点
- 华北区域：北京红星标注
- 色标：底部水平 `[0.2, 0.04, 0.62, 0.02]`
- 标注：右下角 "ARIA-Globe vn.17"

**待补**：中国标准版图 + 省界 shapefile 叠加（需获取 `/home/liangju/shapefiles/` 目录权限）。

输出 `figures/{global,east_asia,north_china}/{ifs,aifs}/`，每次运行先清空旧图。

## 输出目录结构

```
{save_dir}/
├── ifs/                  ← 5 个 .grib2（最新时次）
├── aifs/                 ← 4 个 .grib2
├── ivt/{ifs,aifs}/       ← 9 个 _ivt.nc
├── ar/{ifs,aifs}/        ← 9 个 _ar.nc
├── figures/
│   ├── global/{ifs,aifs}/       ← 9 PDF
│   ├── east_asia/{ifs,aifs}/    ← 9 PDF
│   └── north_china/{ifs,aifs}/  ← 9 PDF
├── log/                  ← 日志
└── .last_run             ← 缓存
```

## 关键设计决策

| 决策 | 原因 |
|------|------|
| 逐模型独立时次 | IFS/AIFS 上线不同步 |
| 缓存下载完即写 | 避免后续阶段失败导致重复下载 |
| 每小时跑但只下载 4 次/天 | ECMWF 约 6h 更新一波，缓存过滤无效运行 |
| AR 跳过已存在文件 | 中断后重跑只补缺失，不重复检测 |
| AR 用 mp.Process 分批并行 | Pool 的 daemon 进程无法再开子进程（FilFinder2D 内部需要） |
| IVT/AR 单文件容错 | 一个文件失败不中断整条管线 |
| 下载失败即退出 | grib2 不完整会导致后续全部失败 |
