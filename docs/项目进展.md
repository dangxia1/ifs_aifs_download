## 脚本指南

| 脚本 | 用途 | 命令 |
|---|---|---|
| `dl_2026.py` | 日常下载（ecmwf 源，ifs+aifs，最近5天） | `python scripts/dl_2026.py` |
| `dl_anytime.py` | 任意日期下载（azure 源，跳过已存在） | `python scripts/dl_anytime.py 2025-03-15 2025-10-31` |
| `check_miss.py` | 检查缺失（先看缺多少再决定补不补） | `python scripts/check_miss.py 2026-05-01 2026-05-07` |
| `setup.py` | 预建目录（首次用，下载时也会自动建） | `python scripts/setup.py 2026-04-01 2026-10-31` |

### 日常工作流

```bash
python scripts/dl_2026.py                              # 1. 每日拉取最近5天
python scripts/check_miss.py 2026-05-01 2026-05-07     # 2. 检查缺口
python scripts/dl_anytime.py 2026-05-01 2026-05-03     # 3. 有缺口就补
```

### 两个下载脚本的分工

| | dl_2026.py | dl_anytime.py |
|---|---|---|
| 数据源 | ecmwf（快，1-2 MB/s） | azure（慢，~200 KB/s） |
| 窗口 | 最近 5 天 | 任意日期 |
| 用途 | 每日增量 | 历史全量 / 补缺口 |
| 策略 | 过期后 404 自动跳过 | 下载所有缺失文件 |

`scripts/config.yaml` — 可调参数：`times`、`steps`、`retry_max`、`retry_interval`、`save_dir`、`log_dir`。

## 文件结构

```
data/raw/
├── 2025/ 或 2026/
│   ├── ifs/
│   │   ├── 0/  6/  12/  24/  48/  72/
│   └── aifs-single/
│       └── 同上
log/
└── {YYYYMM}/
    └── {YYYYMMDD}_download.log
```

每个 step 目录下：`{date}_{model}_t{time}_step{step}.grib2`，内含 40 条 GRIB 消息（4 单层 + 36 气压层）。

## 核心流程

```
遍历 model → date → time → step:
  target 存在 → SKIP（已完成）
  下载 surface + pressure levels → 两个临时文件
  二进制合并 → target.tmp（防止中断留半文件）
  eccodes 校验 40 条消息
    → OK: os.replace → target（原子更名）
    → FAIL: 删除 .tmp，重试
  404 → [EXPIRED] 不重试
  其他异常 → 清理 .tmp → 最多重试 3 次，间隔 10s
```

## 数据量估算

实测单文件大小: IFS ~26MB, AIFS ~23MB。每日 2 模型 × 4 时次 × 6 步 = 48 文件 ≈ 1.16 GB。

| 范围 | 文件数 | 数据量 | ecmwf 耗时 | azure 耗时 |
|---|---|---|---|---|
| dl_2026.py 每次 (2模型×5天×4时次×6步) | 240 | ~6 GB | ~1 小时 | — |
| 单月 (31天) | 1,488 | ~36 GB | — | ~35-60 小时 |
| 2025 汛期 (3.15-10.31, 231天) | 11,088 | ~270 GB | — | **~10 天** |
| 2026 汛期 (4.1-10.31, 214天) | 10,272 | ~250 GB | — | **~10 天** |
| 两季合计 | 21,360 | ~520 GB | — | **~20 天** |

### 处理所需额外空间

| 项目 | 空间 |
|---|---|
| 原始 GRIB2 数据 | ~520 GB |
| ERA5 对比数据 (6小时间隔, 同等参数) | ~40 GB |
| 处理中间产物 (NetCDF 转换 + 诊断量) | ~350 GB |
| 图表和结果 | ~5 GB |
| **建议预留** | **1.2 TB** |

- ecmwf 源：~15s/文件（1-2 MB/s）
- azure 源：~70-300s/文件（80-300 KB/s），挂 VPN 更快
- 下载中断后重跑会自动跳过已完成文件，不丢进度
- 节省空间策略：下载完一批即转换为 NetCDF 并删除 GRIB，可减少 ~250 GB
